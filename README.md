# 运行命令

## 1. 编译命令

```bash
mpicxx -std=c++11 -O2 forest_fire.cpp -o forest_fire
# or
mpicxx -std=c++14 -O2 forest_fire.cpp -o forest_fire
```

- `mpicxx`：MPI 的 C++ 编译器。
- `-std=c++11`：启用 C++11 标准（使用 lambda、auto 等语法必需）。
- `-O2`：编译优化等级。
- `forest_fire.cpp`：源文件名。 
- `-o forest_fire`：输出可执行文件名。

## 2. 测试命令

### 2.1 从输入文件读取网格并单次测试

```bash
mpirun -np 4 ./forest_fire 6 0.0 1 input_grid.txt
```

**含义：**

- `mpirun -np 4`：使用 4 个 MPI 进程执行。
- `./forest_fire`：可执行文件。
- `6`：网格大小 $N=6$，与题目提供的 `input_grid.txt` 中的网格尺寸相匹配。
- `0.0`：此处的 `p` 仅作占位，读取文件时不会用到该值。
- `1`：重复次数 $M=1$。
- `input_grid.txt`：从文件中读取初始网格。

**测试目的：**

- **对应题目**「可以从文本文件读取网格并模拟」的功能验证。
- 检查程序读取并行分发网格、计算火灾蔓延、输出结果等功能是否正确。

### 2.2 随机初始化网格，单次小规模测试 (示例)

```bash
mpirun -np 2 ./forest_fire 10 0.5 1
```

**含义：**

- `-np 2`：使用 2 个 MPI 进程。
- `10`：网格大小 $N=10$。
- `0.5`：每个格子有 0.5 的概率生成树。
- `1`：重复次数 = 1。

**测试目的：**

- **对应题目**「可生成随机网格并进行模拟」的功能。
- 仅进行一次快速测试，确保随机生成及并行通信流程无误。

### 2.3 多次重复 (M 次) 测试收敛性 (示例脚本思路)

题目需要**验证在不同 $p$ 值下、$M=50$ 是否足够收敛**。通常可写脚本循环不同 $p$；示例如下：

```bash
# 示例：在 N=100 下，对 p=0.1, 0.3, 0.5, 0.7, 0.9 做多次重复 (M=50) 测试
mpirun -np 4 ./forest_fire 100 0.1 50
mpirun -np 4 ./forest_fire 100 0.3 50
mpirun -np 4 ./forest_fire 100 0.5 50
mpirun -np 4 ./forest_fire 100 0.7 50
mpirun -np 4 ./forest_fire 100 0.9 50
```

**含义：**

- `-np 4`：4 个进程并行。
- `100`：网格大小 $N=100$（题目示例中也提到可以固定 $N=100$）。
- `0.1 / 0.3 / 0.5 / 0.7 / 0.9`：不同的树初始概率 $p$。
- `50`：重复次数 $M=50$。

**测试目的：**

- 观察**对不同 $p$ 值**时，输出的**平均步数**、**火到达底部的概率**等是否随着 $M$ 的增大而趋于稳定。
- **对应题目**中「验证 $M=50$ 是否足以达到收敛，以及是否依赖于 $p$」的要求。

如果想更细致地研究收敛过程，可针对同一个 $p$ 循环多种 $M$：比如 $M=10,20,30,40,50,60,80,100$ 等，收集结果后进行比较。

### 2.4 不同网格大小 $N$ 的性能测试

题目中要求对 $N=50, 100, 500$，并在**固定 $p=0.6$，$M=50$** 的条件下，改变 MPI 并行进程数进行性能分析。我们可执行一系列命令，示例如下：

#### 2.4.1  (1) $N = 50$

```bash
# 1 个进程(串行)
mpirun -np 1 ./forest_fire 50 0.6 50
# 2 个进程
mpirun -np 2 ./forest_fire 50 0.6 50
# 4 个进程
mpirun -np 4 ./forest_fire 50 0.6 50
# 8 个进程
mpirun -np 8 ./forest_fire 50 0.6 50
```

#### 2.4.2 (2) $N = 100$

```bash
# 1 个进程
mpirun -np 1 ./forest_fire 100 0.6 50
# 2 个进程
mpirun -np 2 ./forest_fire 100 0.6 50
# 4 个进程
mpirun -np 4 ./forest_fire 100 0.6 50
# 8 个进程
mpirun -np 8 ./forest_fire 100 0.6 50
# 16 个进程(如果资源允许)
mpirun -np 16 ./forest_fire 100 0.6 50
```

#### 2.4.3 (3) $N = 500$

```bash
# 1 个进程
mpirun -np 1 ./forest_fire 500 0.6 50
# 2 个进程
mpirun -np 2 ./forest_fire 500 0.6 50
# 4 个进程
mpirun -np 4 ./forest_fire 500 0.6 50
# 8 个进程
mpirun -np 8 ./forest_fire 500 0.6 50
# 16 个进程
mpirun -np 16 ./forest_fire 500 0.6 50
# 32 个进程(如机器允许)
mpirun -np 32 ./forest_fire 500 0.6 50
```

**含义：**

- `N=50 / 100 / 500`：三种不同规模网格。
- `p=0.6`：固定概率。
- `M=50`：每种情况下都做 50 次重复，用于稳定结果。
- `-np 1, 2, 4, 8, 16, ...`：进程数从串行到较多并行时，测量运行时间。

**测试目的：**

- **对应题目**「进行并行性能分析」，考察在三种网格大小下，随着进程数增加，程序运行时间如何变化（Walltime、Speedup、并行效率等指标）。
- 分析**通信开销**与**计算规模**的关系，找出“最佳”并行规模或并行效率变化规律。
- **题目要求**「给出最大可用 MPI 任务数量并解释原因」，这要结合实际观察到的速度变化与硬件资源限制。
